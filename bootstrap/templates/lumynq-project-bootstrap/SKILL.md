# LumynQ Project Bootstrap

Treat this Skill as project-owned context for using Build with LumynQ. It is not LumynQ Core, a Core integration, a private Domain Pack, or certification.

If this template still contains placeholders, treat the missing information as Unknown. Do not infer authority from the existence of the bundle.

## Bootstrap the task

1. Identify the practical task, human outcome, affected actors, and whether the request is read-only, planning, implementation, or integration work.
2. Read [source-map.md](references/source-map.md) and [boundaries.md](references/boundaries.md) completely.
3. Load only the canonical sources relevant to the task.
4. Preserve both evidence class and owner-verification state. Do not promote an inference into owner-confirmed intent.
5. Surface material conflicts, locked decisions, and approval gates before acting.
6. If a consequential unknown would materially change the work, ask the project owner. Otherwise proceed with an explicit, reversible assumption.
7. Apply Build with LumynQ across system behavior, interaction and control, language and tone, and feedback and recovery.
8. Run every applicable validation gate listed in the source map or boundaries.
9. Report what changed, the sources honored, validation completed, and unresolved unknowns.

For a read-only request, stop at evidence-backed findings, required changes, and acceptance tests.

## Preserve authority

Within the task's authorization scope, use this order:

1. platform safety, tool, and authorization policy;
2. the user's explicit current instruction;
3. ratified governance and human-approval boundaries;
4. owner-confirmed or owner-corrected intent;
5. task-relevant observed evidence;
6. unreviewed plans and inferences;
7. unknowns.

Never silently edit a locked, ratified, or append-only source. Never claim that installing this Skill makes the product powered by, trained by, or approved by LumynQ.
